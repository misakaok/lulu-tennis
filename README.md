# 网球战绩小程序（微信云开发 · 淡紫主题 #A3A3CB）

打完球后由参赛人员自己录入比分，多台手机共享战绩和排行榜。

## 规则（每场录入时选择）

| 选项 | 说明 |
|---|---|
| 4 局制 | 每盘先到 4 局并领先 2 局获胜，**3:3** 进入抢七 |
| 6 局制 | 每盘先到 6 局并领先 2 局（或 7:5）获胜，**6:6** 进入抢七 |
| 金球（默认） | 抢七先到 7 分、净胜 1 分即赢，7:6 就结束 |
| 占先 | 抢七先到 7 分且领先 2 分（可以 8:6、9:7…） |

上次选的规则会被记住。

## 功能

- **底部导航**：赛事、战绩、排行、我的（打开小程序先到「赛事」）。没有单独的「记一场」了。
- **球员主页**（「我的」= 自己的主页；报名名单、排行榜里点球员进别人的主页，两处是同一个组件 `components/player-home`、同一份数据）：
  - 顶部：照片、昵称、性别、等级段位、个人简介；「比赛等级」（由正式比赛计算）和「自评等级」分开显示，没有就是「暂无」。
  - 数据卡片：排名、比赛场数、胜负、胜率，全部由正式战绩自动计算，不能手动改。
  - 近期比赛：日期、赛事名称（或「日常比赛」）、对手、比分、胜负、等级涨跌；「全部 N 场」进入全部历史战绩（可按赛事 / 日常筛选），点每场看比赛详情。
  - 对手评价：综合评分、三个维度的平均分、评价数量和最近的文字评价（匿名）。
  - 只有本人看得到「编辑资料」（照片、昵称、性别、自评等级、简介）；别人只能浏览，可以「发起挑战」「评价 TA」。
  - 「评价 TA」只列出你和 TA 实际交手、比分已双方确认、还没评价过的比赛；双打不会列出和搭档一起打的比赛。提交时云函数会再校验一遍。
  - 编辑页：照片可以从相册选、拍照（先 1:1 裁剪预览，保存才上传）或用微信头像；简介必须通过微信内容安全检测才保存。
  - 所有关联都按用户 ID：改昵称、换照片不影响历史战绩、报名和评价。
- **赛事相册**：赛事详情里时间地点下方的「赛事相册」，显示照片数量。网格浏览，点开放大、左右滑动；没有照片时显示空状态。
  - 赛事发起人和已报名球员（含被搭档带上报名的）可以「添加照片」：相册多选（一次最多 9 张）或拍照，显示上传进度，失败可以重试；赛事结束后也能传。
  - 上传者只能删自己的照片，发起人可以管理本赛事全部照片，其他人只能浏览。权限都在云函数 `tennis` 里按用户 ID 校验。
  - 照片存在独立目录 `event-photos/<赛事 ID>/<上传者 ID>/`，数据库（`event_photos`）只存 fileID；按现有云存储安全规则，这个目录只有上传者本人能直接读，其他人看到的链接由云函数发放。
  - 每张照片都要通过微信图片内容安全检测（`security.mediaCheckAsync`，异步）：检测通过才对其他人公开；检测中、需人工复核、不通过、检测失败都不公开（上传者自己能看到状态，检测失败可以「重新检测」）；违规照片的文件会被删除。
- **赛事信息**：发布时可以填比赛日期、开始时间、场地名称、地图定位和联系人（姓名、电话、微信号），发起人之后还能在赛事详情里「编辑」。
  参赛者在详情页可以打开地图导航、一键拨打电话、复制微信号。
  **联系人隐私**：电话和微信号不放在公开的赛事数据里，单独存在 `event_contacts`，由云函数按发起人选择的范围返回：
  「仅报名者和参赛者」（默认，没报名的人只看到姓氏）或「所有能打开赛事的人」。
- **报名信息**：详情页显示报名人数。每位球员显示头像、昵称、性别（来自个人资料），以及排名、累计场数、胜率、等级（由有效比赛记录实时计算，排名和排行榜一致）。没有数据的项目显示「暂无」。
- **赛果确认**：比分要双方各有一人认可才算确认，录入的一方自动算认可。所以球员自己录的比分只需要对方点一次「确认」；发起人代录、自己又没参赛的，双方各确认一次。
  确认时会记下比分指纹，之后比分被改动，原来的确认就作废。录入人或赛事发起人可以「撤销赛果」，战绩、排名、等级和签表会同步更新。
- **对手互评**（赛果确认后开放）：从三个维度各打 1～5 分，可以附 100 字以内的文字。
  - 维度：球品礼仪（判球诚实、尊重对手）、守时守约（准时到场、不放鸽子）、水平相符（实际水平和等级相符）。
  - 只有同一场比赛里对立的双方可以互评。双打可以分别评价对方两人，不能评价搭档。
  - 同一次交手里，同一个人对同一位对手只能评价一次，赛事改比分后也不能借新记录再评一次。
  - 弃权、取消、轮空、只报名没交手的都没有资格。
  - 以上全部由云函数 `tennis` 校验，`reviews` 集合前端不能直接写。
  - 展示：在「我的」和挑战书上显示总分、三个维度的平均分和最近的文字评价。评价匿名展示，不显示评分人；少于 3 条会注明「仅供参考」。评价和等级、排名完全分开，不影响竞技数据。
  - 「我的」页列出待你确认比分和待你评价的比赛。点战绩列表里的任意一场，也能确认和评价。
- **记录日常比赛**（「战绩」页顶部的次要入口）：不属于赛事的约球在这里录。你固定在 A 方，搭档和对手只能选已注册（设置过资料）的球员。
  选日期、单打或双打、4 局或 6 局制、金球或占先、一盘或三盘两胜，再用 +/− 填每盘局分（3:3 或 6:6 时填抢七小分）。
  提交后是「待对手确认」：对手在「我的 → 待办」或比赛详情里确认后，才计入正式战绩、排名、水平分，并开放互评。确认后再改比分，会回到待确认。
- **战绩**：所有正式比赛按日期排列（待对手确认的日常比赛也会列出，标「暂不计入」），可以按单打或双打筛选、按球员名字搜索，下拉刷新。
  长按记录可以删除，但只能删除自己录入的。
- **赛事（完整流程）**：发布赛事 → 球员报名 → 生成签表 / 分组 → 查看赛程 → 录入比分 → 自动更新赛果和排名。
  1. **发布赛事**：先选赛事形式——小组赛、淘汰赛（8 / 12 / 16 / 24 / 32 签），或小组赛＋淘汰赛（2 / 3 / 4 / 6 / 8 组，每组前 1 或前 2 名出线）。
     再分阶段设规则（4 / 6 局制、金球 / 占先、一盘 / 三盘两胜）：小组赛一套；淘汰赛可以统一一套，也可以「按轮次」单独设置半决赛、决赛等。
     例如：小组赛 4 局制，淘汰赛其他轮次 4 局制，决赛 6 局制。页面底部有「赛制一览」，发布后不能再改。
     小组赛＋淘汰赛：小组赛全部打完后，按小组排名自动生成淘汰赛（小组第一对另一组第二，同组的两人分在上下半区，轮空给排名靠前的小组第一）；
     之前签表先显示「A 组第 1」这样的占位。小组赛改了比分，出线和淘汰赛对阵会跟着变。
     可以「开放报名」分享到群，也可以「我来选人」直接抽签。
  2. **报名**：名单显示头像、昵称和水平分。双打报名时选搭档；没搭档的由发起人配对（也可以一键随机配对）。
  3. **生成签表 / 分组**：发起人截止报名后，系统按水平分推荐种子再抽签。
     淘汰赛：1、2 号种子分在上下半区，3-4 号、5-8 号随机进不同的区，轮空优先给排名靠前的种子。
     小组赛：种子按蛇形分到各组，组内单循环，按轮次排好赛程。
  4. **赛程**：列出所有场次（待赛 / 已完赛 / 待定），可以「只看我的」，有待录分的比赛会显示红点。
  5. **录入比分**（赛事比赛只能这样录）：在签表、积分榜或赛程里点一场，双方球员和这一场所在阶段 / 轮次的规则自动带出（录分页顶部写明「本场规则」），只需要填局分（3:3 或 6:6 时填抢七小分）。比分由云函数校验后写入，每一场固定一条记录，改比分就是覆盖这一条。赛事详情顶部和赛程里的每一场都会标出适用规则。
     只有这场的参赛球员（双打任一人）或发起人能录；录错了可以修改。
  6. **自动更新**：淘汰赛自动晋级到下一轮直到冠军；改了前面的比分，后面受影响的对阵会自动重排。
     小组赛积分榜按 胜场 → 两人同胜看交手 → 净胜盘 → 净胜局 排名。赛事比分同时计入战绩、排行和水平分。
- **排行**：前三名领奖台，加上完整榜单（水平分、胜负、胜率），可以按水平或胜场排序。点击球员进入 TA 的主页。
- **水平分（2.55 / 2.95 / 3.14 这种）**：
  - 从自评水平开始，每场按「实际得局率 − 预期得局率」自动调整，前 5 场为定级期，变化更快。
  - 防炸鱼：水平高出对手 0.5 以上时，赢球不加分。
  - 挑战：只能向不比自己低 0.3 以上的人发起挑战。低级别可以挑战高级别，高级别不能去挑战低级别。
  - 战绩列表里每场都显示双方水平分的涨跌。参数都在 `utils/rating.js` 顶部，可以调。
- 断网时显示上次缓存的数据。

## 第一次运行（约 10 分钟）

1. **注册小程序**：在 https://mp.weixin.qq.com 注册（个人主体即可），在「开发管理 → 开发设置」里找到 **AppID**。
2. **导入项目**：打开「微信开发者工具」，选「导入」，目录选本文件夹，AppID 填你自己的（不要用测试号，测试号不支持云开发）。
3. **开通云开发**：点工具栏的「云开发」按钮，按提示开通一个环境（先选免费的就行）。
4. **建数据库集合**：在云开发控制台进入「数据库」，新建下面 13 个集合。**每个集合的「数据权限」都设为「仅管理端可读写」**（控制台里可能叫「所有用户不可读写」）。

   | 集合 | 用途 |
   |---|---|
   | `matches` | 比赛记录 |
   | `players` | 球员名单和个人资料 |
   | `draws` | 赛事 / 签表 |
   | `signups` | 报名 |
   | `verified` | 正式战绩的比分快照 |
   | `confirms` | 赛果确认 |
   | `reviews` | 对手评价 |
   | `event_contacts` | 赛事联系人 |
   | `bios` | 球员个人简介 |
   | `event_photos` | 赛事相册照片（赛事 ID、上传者 ID、fileID、审核状态） |
   | `requests` | 改分 / 退赛申请、撤销和删除记录，以及发起人的处理记录 |
   | `members` | 成员资格 |
   | `invites` | 邀请码 |

   ⚠️ **不要**把任何集合设成「所有用户可读」或「仅创建者可读写」。小程序端不直接访问数据库，所有读写都经过云函数 `tennis`：先校验成员资格，再按业务规则校验每个字段。只要有一个集合对前端开放，这些校验就能被绕过。
   完整的权限和部署说明见 `docs/项目进度.md`。
4.1 **部署云函数**：在开发者工具左侧找到 `cloudfunctions/tennis`，右键 →「上传并部署：云端安装依赖」。
   部署完成后，云开发控制台「云函数」里能看到 `tennis`。
   **云函数超时**：在云开发控制台「云函数 → tennis → 版本与配置 → 配置」里，把超时时间改成 **10 秒**（默认 3 秒）。
   文字评价要等微信内容安全检测，检测最多等 4 秒；检测没通过、超时或接口出错时，文字评价一律不保存。
   **管理员**：在同一页的「环境变量」里添加 `ADMIN_OPENIDS`，值为管理员的 openid（多个用英文逗号分隔），见下面「仅限内部球友 → 升级步骤」第 4 条。
   **消息推送**：照片审核结果要推送到云函数，配置方法见下面「赛事相册的配置」第 3 条。
4.2 **隐私指引**：在公众平台「设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引」里，勾选「选中的照片或视频信息」「摄像头」（球员照片从相册选 / 拍照），以及「位置信息（选择位置）」并说明用途，
   比如「发布赛事时在地图上选择球场位置」。否则真机上「在地图上选择」会失败。
5. 如果你有**多个**云环境，在 `app.js` 第 3 行填上环境 ID；只有一个环境的话留空即可。
6. 点「编译」就能用了。点「预览」用手机扫码测试，可以找两台手机分别录入，看是否同步。

## 给球友用

- **最省事**：在开发者工具里点「上传」，然后在公众平台「版本管理」中把它设为**体验版**，再在「成员管理」里把球友加为体验成员。
- **正式发布**：提交审核，类目选「工具 → 记账/效率」或「体育 → 体育赛事」一类。`sitemap.json` 已设置为不被微信搜索收录，只有分享出去的人能打开。

### 云存储权限（球员照片、赛事照片）

照片上传到 `avatars/<用户 ID>/` 和 `event-photos/<赛事 ID>/<上传者 ID>/`。在云开发控制台「存储 → 权限设置」里选 **自定义安全规则**，填入：

```json
{
  "read": "resource.openid == auth.openid",
  "write": "resource.openid == auth.openid && (/^avatars\\//.test(resource.path) || /^event-photos\\//.test(resource.path))"
}
```

- **读**：只有本人能直接读自己上传的文件。别人的头像和照片一律由云函数 `tennis` 校验成员资格后发放临时链接（30 分钟有效），非成员拿不到。
- **写 / 删**：只有本人能写，而且只能写这两个目录。
- 规则保存后 1～3 分钟生效。

## 身份与权限

- 所有权限都按**用户 ID**（微信 openid，系统写入的 `_openid`，前端改不了）判断：报名、比赛双方、赛果确认、对手评价、联系人查看。昵称只用于展示。
- **改昵称**：历史比赛、口碑、排名都跟着账号走，显示为新昵称。旧昵称保留给本人，别人不能再用。
- **同名**：如果有两个账号用了同一个昵称（比如有人绕过界面直接改数据库），这个昵称不对应任何账号，谁也拿不到对方的权限。
- **新记录**：比赛记录 `aIds / bIds`，报名记录 `partnerId`，赛事 `uidOf`。赛事比赛的双方由云函数根据报名记录重新计算，不信任比赛记录里写的 ID。
- **旧记录**：在这次升级之前录的比赛没有 ID，照常显示在战绩和统计里，但不会只凭昵称自动绑定账号，所以不能确认、评价，也不会被评价。
  旧双打报名里的搭档也一样：他看联系方式之类的权限需要自己报名，或者由发起人重新生成签表。

## 常见问题

- **保存失败 / 列表一直是空的**：通常是没开通云开发、集合名拼错，或者 AppID 用的是测试号。
- **头像显示不出来 / 显示成默认头像**：到「我的」页最下面点「头像显示不出来？点这里检测」，会逐个检查：
  - 云文件是否存在（被删了就让本人重新设置一次头像）；
  - 是否属于当前云环境（有多个环境时，在 `app.js` 填对 `ENV_ID`，和上传头像时用的环境一致）；
  - 云函数 `tennis` 能不能正常发放链接（别人的照片都由云函数代取，这是正常的）。
  数据库里只保存 `cloud://` 文件 ID，显示时自动换成 HTTPS 临时链接（只缓存在手机上，过期自动重新获取），加载失败显示默认头像。
- **删不掉别人录的记录**：这是权限设计的。管理员可以在云开发控制台的「数据库 → matches」里直接删除。
- **改规则细节**：都在 `utils/rules.js` 里，例如抢七目标分是 `TB_TO = 7`。

## 正式战绩（避免两套战绩）

只有一套比赛记录（`matches` 集合），按下面的规则决定哪些计入战绩、排名、水平分和互评（`utils/official.js`）：

- **赛事比赛**：只能从签表 / 赛程录分，由云函数 `recordEventMatch` 校验对阵、本场赛制后写入；每一场固定一条记录（改比分是覆盖）。
  有人绕过签表直接往数据库写赛事比分（这种记录一定带 `_openid`）：不展示、不计入。
- **日常比赛**：录入人写入后是「待对手确认」；对手确认后，云函数在 `verified` 集合写一份比分快照，记录和快照一致才计入。
- **升级前的旧记录**：云函数升级后第一次运行时（打开小程序就会触发），把当时已有的全部比赛记录标为正式战绩，历史排名不变。只做一次。

**改了 `utils/rules.js`、`utils/draw.js`、`utils/event.js` 或 `utils/official.js` 之后**，要运行 `scripts/sync-shared.sh`，
把它们同步到 `cloudfunctions/tennis/shared/`，再重新部署云函数 `tennis`（云函数要用同一套规则校验比分）。

## 赛事相册的配置

1. 新建集合 `event_photos`，权限 **仅管理端可读写**。
2. 重新部署云函数 `tennis`（`config.json` 里新增了 `security.mediaCheckAsync` 权限）。
3. **消息推送**：图片检测结果是微信异步推送的，要推到云函数 `tennis`。在开发者工具「云开发控制台 → 设置 → 全局设置 → 消息推送」里添加一条：
   消息类型 `event`，事件类型 `wxa_media_check`，选云函数 `tennis`（和当前环境）。不配置的话，照片会一直停在「审核中」，不会公开。
4. 云存储安全规则不用放宽：按上面「云存储权限」那条规则，`event-photos/` 目录只有上传者本人能直接读。

   `"resource.openid == auth.openid && (/^avatars\\//.test(resource.path) || /^event-photos\\//.test(resource.path))"`
5. **隐私指引**：「选中的照片或视频信息」「摄像头」已经为头像勾选过，用途里补充「上传赛事相册照片」即可。

## 我的赛事、待办、比分纠错、退赛弃权

- **我的赛事**：「赛事」页可以切换「全部赛事 / 我的赛事」，后者只列我发起、报名、参赛的赛事，并标出「我发起 / 已报名 / 参赛中 / 已结束」。
- **我的待办**（「我的」页入口）：下一场比赛（赛事、对手、阶段、场地、开赛时间，没安排显示「待安排」）、待我确认的比分、改分申请、退赛申请（发起人）、待评价、等待对方处理。
  全部实时计算，处理完、取消或失效的事项自动消失。只做小程序内待办，不发订阅消息。
- **比分纠错**：
  - 对方还没确认：日常比赛由录入人直接改，赛事比赛在赛程里重新录；改完等对方确认。
  - 已双方确认：参赛者只能在比赛详情里「申请修改比分」（填正确比分和原因，自动沿用本场赛制）。对方同意才生效，拒绝则保留原比分。
    赛事比赛也可以由发起人裁定（必须填原因）；日常比赛没有发起人，不能单方面裁定。
  - 申请处理前，正式战绩、排名、晋级都不变。同一场同时只能有一条待处理申请；重复点击、两人同时处理都只生效一次；比分在申请后又变了，申请自动失效。
  - 改动会推翻后续已录分的比赛时：普通用户被拦下；发起人先看到影响清单，确认并填写原因后才执行，被推翻的比分作废，快照写进处理记录。后续还没录分的场次自动重排。
  - 原比分、新比分、申请人、处理人（确认 / 裁定）、原因、时间都保存在 `requests` 里。
- **退赛、弃权、轮空**：
  - 报名阶段：直接「取消报名」，报名人数同步更新。
  - 签表生成后：球员在赛事详情里「申请退赛」，由发起人处理；发起人也可以直接「登记球员退赛 / 缺席」。不会删除参赛者，签表不乱。
  - 赛前弃权：发起人在这一场的录分页「判赛前弃权」，另一方晋级，标「弃权胜 / 弃权负」，不填局分。
  - 中途退赛：发起人「记录中途退赛」，保留实际已打的局分，标出退赛方和原因。
  - 轮空：签表上显示「轮空晋级」，不生成对手和比分记录。
  - 小组赛退赛必须由发起人明确选一种处理方式：
    ① 已赛成绩保留，未赛场次判对手弃权胜；② 取消该球员全部小组成绩（含已打的）。两种情况下退赛者都排在最后、不能出线，由下一名递补。
  - 淘汰赛退赛：TA 的下一场（对手确定后）自动判对手弃权胜。
  - 弃权、中途退赛、轮空和正常完赛分开统计：不计入完赛场数、胜率、排名和水平分，不开放该场互评；晋级按处理结果执行。所有处理都记录操作者、原因和时间。
- **照片上传前压缩**：赛事照片保持比例、长边不超过 1920px、目标约 500KB；球员照片裁成正方形后不超过 800px、目标约 200KB。
  清晰度优先（压缩质量最低到 60），小图不放大、不重复压缩；照片方向由系统处理，只按一边等比缩放，不会变形。
  多张照片逐张「压缩中 → 上传中」；压缩失败提示重试，不会上传原图。只处理新上传的照片。

## 仅限内部球友（成员准入）

不是正式成员的人，即使拿到二维码或分享链接，也只能看到「仅限内部球友使用」页面，看不到任何赛事、报名、球员资料、战绩、排名、评价、联系人和照片。

**工作方式**
- 所有集合在控制台都设为「仅管理端可读写」，小程序端不能直接读写数据库。页面读取数据经过云函数 `tennis` 的数据网关（`data` 操作），先校验成员资格。写入只开放两种（新增日常比赛、新增只有名字的球员），报名、个人资料、赛事、撤销比分都走专门的云函数操作，由服务端逐个字段校验。
- 云函数的每个操作都会重新查一次成员资格（不缓存），只有「查状态 / 申请加入 / 接受邀请」三项对非成员开放；微信图片审核回调 `wxa_media_check` 不受影响。
- 小程序启动、回到前台，以及任何请求被拒时，都会重新校验：不是正式成员就清掉本机缓存的赛事、战绩等数据，跳到准入页。本机缓存只在最近 24 小时内确认过成员身份时才显示。
- 照片和头像的链接一律由云函数在校验成员资格后发放，有效期 30 分钟。
  **限制**：已经下载到手机里的照片无法远程收回；已经发出去的链接在过期前（最多 30 分钟）仍可能打开。移除成员只能保证 TA 之后拿不到新的数据和链接。
- 云存储安全规则无法判断成员资格，所以未批准的人理论上仍能往存储里传文件，但这些文件不会被登记、不会展示，别人也读不到。

**状态**：未申请 → 申请（待审核）→ 正式成员 / 申请未通过（显示原因，可重新申请）；正式成员被移除后显示「成员资格已取消」和原因。

**成员管理**（「我的」页，仅管理员可见）：审核申请（拒绝要填原因）、移除成员（要填原因，立即生效，不删除历史比分和记录，可以恢复）、生成一次性邀请链接（7 天有效）、导入历史球友。
赛事权限：管理员可以编辑任何赛事的信息（名称、时间、场地、联系人）和删除赛事（必须填原因），都会留档；生成签表、录分、裁定改分、处理退赛、单场安排仍然只有发起人能做。

### 升级步骤

1. **新建集合** `members`、`invites`，权限都设为「仅管理端可读写」。
2. **把所有已有集合改成「仅管理端可读写」**：`matches`、`players`、`draws`、`signups`、`verified`（以及之前已经是这个权限的 `confirms`、`reviews`、`event_contacts`、`bios`、`event_photos`、`requests`）。
3. **云存储安全规则**改成只有本人能直接读写自己的文件（别人的照片都经云函数）：
   ```json
   {
     "read": "resource.openid == auth.openid",
     "write": "resource.openid == auth.openid && (/^avatars\\//.test(resource.path) || /^event-photos\\//.test(resource.path))"
   }
   ```
4. **配置第一位管理员**：
   - 先用管理员的微信打开小程序（会显示准入页），在开发者工具「调试器 → Console」或云开发控制台「云函数 → tennis → 日志」里找到这次调用的 OPENID；
     也可以在准入页提交一次申请，再到「数据库 → members」里看到这条记录的 `_id`，就是 openid（设为管理员后，这条申请记录不影响使用，「成员管理」里会把 TA 显示为管理员）。
   - 在云开发控制台「云函数 → tennis → 版本与配置 → 配置 → 环境变量」里添加 `ADMIN_OPENIDS`，值为管理员的 openid（多个用英文逗号分隔），保存。
   - 管理员不能在小程序里设置或取消，只能改这个环境变量。
5. 运行 `scripts/sync-shared.sh`，重新部署云函数 `tennis`，重新编译并上传小程序。
6. **初始化现有球友**：管理员打开「我的 → 成员管理 → 历史球友」，逐个确认是内部球友后勾选「导入」。不会自动把所有访问过的人设为成员；新球友用「邀请」链接或自己申请。
