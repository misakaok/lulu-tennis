打完球后由参赛人员自己录入比分，多台手机共享战绩和排行榜。

## 规则（每场录入时选择）

| 选项 | 说明 |
|---|---|
| 4 局制 | 每盘先到 4 局并领先 2 局获胜，**3:3** 进入抢七 |
| 6 局制 | 每盘先到 6 局并领先 2 局（或 7:5）获胜，**6:6** 进入抢七 |
| 金球（默认） | 抢七先到 7 分、净胜 1 分即赢，7:6 就结束 |
| 占先 | 抢七先到 7 分且领先 2 分（可以 8:6、9:7…） |

上次选的规则会被记住。

## 功能

- **底部导航**：活动、战绩、排行、我的（打开小程序先到「活动」）。没有单独的「记一场」了。
- **球员主页**（「我的」= 自己的主页；报名名单、排行榜里点球员进别人的主页，两处是同一个组件 `components/player-home`、同一份数据）：
  - 顶部：首字圆、昵称、性别、等级段位；「比赛等级」（由正式比赛计算）和「自评等级」分开显示，没有就是「暂无」。
  - 数据卡片：排名、比赛场数、胜负、胜率，全部由正式战绩自动计算，不能手动改。
  - 赛季和生涯成就：赛季按比赛日期的自然年筛选；冠军、连胜、徽章由正式战绩实时计算。
  - 等级走势：最近 30 场比赛后的比赛等级，一场一根柱子，绿涨红跌。
  - 我和 TA 的交手（只在别人的主页显示）：交手场数、我的胜负和最近 5 场比分；单打和双打里分在两边的都算，弃权 / 退赛不计胜负。
  - 双打搭档：和每位搭档一起打的场数、胜负、胜率；「最佳搭档」从一起打满 3 场的搭档里选胜率最高的。
  - 赛季总结：点「赛季战绩」里的某个赛季，进入这一年的总结页（场数、胜负、每月场数、单双打、最长连胜、等级变化、交手最多的对手、最佳搭档、冠军），可以分享。
  - 近期比赛：日期、活动名称（或「日常比赛」）、对手、比分、胜负、等级涨跌；「全部 N 场」进入全部历史战绩（可按活动 / 日常筛选），点每场看比赛详情。
  - 只有本人看得到「编辑资料」（昵称、性别、自评等级）；别人只能浏览，可以「发起挑战」。
  - 性别必填（男 / 女）。名字旁边会显示性别的地方：球员主页、报名名单、排行榜、挑战书、记录日常比赛的选人、战绩列表、比赛详情、活动赛程。老成员没选的，管理员可以在成员管理里补选。
  - 所有关联都按用户 ID：改昵称不影响历史战绩和报名。
- **活动信息**：比赛名称手动输入（必填、最多 20 个字），日期和赛制变动不会覆盖名称；名称通过云端内容检测后才保存。创建时选择比赛日期、开始时间、场地编号（1～30 号场，可留空）和地图定位，发起人之后还能在活动详情里「编辑」。场地不再自由输入名称，地图只保存坐标。
  参赛者在详情页可以打开地图导航。发起人还可以给某一场单独选择日期、时间、场地编号。旧活动名称和历史战绩中的名称快照保留；退赛原因不在公共名单显示，改分申请原因只供参赛者及发起人处理时查看。创建活动只能从已有球员里选人，不能手写新球员；球员主页、赛季总结、挑战书的分享标题用固定文案，不带昵称。手动名称仍存在个人主体类目审核风险。下文所有「填原因」的地方（改分、裁定、退赛、弃权、撤销、删除活动、拒绝 / 移除成员）都是从固定选项里选，不能手写；准入页只填称呼，没有申请说明。详细检查见 `docs/审核页面检查.md`。
- **报名信息**：详情页显示报名人数。每位球员显示首字圆、昵称、性别（来自个人资料），以及排名、累计场数、胜率、等级（由有效比赛记录实时计算，排名和排行榜一致）。没有数据的项目显示「暂无」。
- **录分即生效**：日常比赛和活动比赛都是有一个人录了就计入战绩、排名和水平分，不需要对方确认。
  - 日常比赛没有「确认」这一步。
  - 活动比赛保留「确认」：双方各有一人认可（录入的一方自动算认可）后比分**锁定**，之后修改要走申请；不确认也照常计入。确认时记下比分指纹，比分再被改动，原来的确认就作废。
  - 录入人、活动发起人或管理员可以「撤销赛果」，战绩、排名、等级和签表会同步更新（规则见下面「比分纠错」）。
- **记录日常比赛**（「战绩」页顶部的次要入口）：不属于活动的约球在这里录。只能记录自己参加的比赛（云函数按用户 ID 校验），你固定在 A 方，搭档和对手只能选已注册（设置过资料）的球员。
  选日期、单打或双打、4 局或 6 局制、金球或占先、一盘或三盘两胜，再用 +/− 填每盘局分（3:3 或 6:6 时填抢七小分）。
  提交后直接生效，计入正式战绩、排名、水平分，不需要对手确认。录错了，录入人和参赛者都可以在比赛详情里直接修改。
- **战绩**：所有正式比赛按日期排列，可以按单打或双打筛选、按球员名字搜索，下拉刷新。
  长按记录可以删除，但只能删除自己录入的日常比赛；管理员要撤销别人的比赛，在比赛详情里操作。
- **活动（完整流程）**：创建球友活动 → 球员报名 → 生成签表 / 分组 → 查看赛程 → 录入比分 → 自动更新赛果和排名。
  0. **活动列表**：可以切换「全部活动 / 我的活动 / 日历」。日历按月显示，有活动的日子带圆点（我的活动是实心），点某一天只看那天的活动。
  1. **创建球友活动**：先选活动形式——小组赛、淘汰赛（8 / 12 / 16 / 24 / 32 签），或小组赛＋淘汰赛（2 / 3 / 4 / 6 / 8 组，每组前 1 或前 2 名出线）。
     再分阶段设规则（4 / 6 局制、金球 / 占先、一盘 / 三盘两胜）：小组赛一套；淘汰赛可以统一一套，也可以「按轮次」单独设置半决赛、决赛等。
     例如：小组赛 4 局制，淘汰赛其他轮次 4 局制，决赛 6 局制。页面底部有「赛制一览」，创建后不能再改。
     小组赛＋淘汰赛：小组赛全部打完后，按小组排名自动生成淘汰赛（小组第一对另一组第二，同组的两人分在上下半区，轮空给排名靠前的小组第一）；
     之前签表先显示「A 组第 1」这样的占位。小组赛改了比分，出线和淘汰赛对阵会跟着变。
     可以「开放报名」分享到群，也可以「我来选人」直接抽签。
     **组别**：不限、男子、女子，双打还可以选混双。报名时云函数按个人资料里的性别校验：男子 / 女子组只收对应性别，混双的搭档必须一男一女，没选性别的要先去选。「我来选人」不自动检查性别。
     **报名上限和候补**：淘汰赛的名额就是签数；小组赛可以设报名上限（不设就不限）。名额满了仍然可以报名，排进候补；按报名先后排队，前面有人取消，后面的自动递补。截止报名生成签表时，候补的默认不参赛，发起人可以手动点选。
  2. **报名**：名单显示首字圆、昵称、性别、排名、场数、胜率和等级。双打报名时选搭档；没搭档的由发起人配对（也可以一键随机配对）。
  3. **生成签表 / 分组**：发起人截止报名后，系统按水平分推荐种子再抽签。
     淘汰赛：1、2 号种子分在上下半区，3-4 号、5-8 号随机进不同的区，轮空优先给排名靠前的种子。
     小组赛：种子按蛇形分到各组，组内单循环，按轮次排好赛程。
  4. **赛程**：列出所有场次（待赛 / 已完赛 / 待定），可以「只看我的」，有待录分的比赛会显示红点。
  5. **录入比分**（活动比赛只能这样录）：在签表、积分榜或赛程里点一场，双方球员和这一场所在阶段 / 轮次的规则自动带出（录分页顶部写明「本场规则」），只需要填局分（3:3 或 6:6 时填抢七小分）。比分由云函数校验后写入，每一场固定一条记录，改比分就是覆盖这一条。活动详情顶部和赛程里的每一场都会标出适用规则。
     只有这场的参赛球员（双打任一人）或发起人能录；对方确认前录错了可以直接重录，改分会留档。
  6. **自动更新**：淘汰赛自动晋级到下一轮直到冠军；改了前面的比分，后面受影响的对阵会自动重排。
     小组赛积分榜按 胜场 → 两人同胜看交手 → 净胜盘 → 净胜局 排名。活动比分同时计入战绩、排行和水平分。
- **排行**：前三名领奖台，加上完整榜单（水平分、胜负、胜率），可以按水平或胜场排序，可以按赛季查看（水平分不分赛季），可以按性别筛选（名次在筛选后重新排）。点击球员进入 TA 的主页。
  另有三个趣味榜单：本月活跃（本月完赛场数）、连胜（当前连胜场数）、本月进步（本月等级涨幅），都由正式战绩计算，只算正常完赛的比赛。
- **水平分（2.55 / 2.95 / 3.14 这种）**：
  - 从自评水平开始，每场按「实际得局率 − 预期得局率」自动调整，前 5 场为定级期，变化更快。
  - 防炸鱼：水平高出对手 0.5 以上时，赢球不加分。
  - 挑战：只能向不比自己低 0.3 以上的人发起挑战。低级别可以挑战高级别，高级别不能去挑战低级别。
  - 战绩列表里每场都显示双方水平分的涨跌。参数都在 `utils/rating.js` 顶部，可以调。
- 断网时显示上次缓存的数据。

## 第一次运行（约 10 分钟）

1. **注册小程序**：在 https://mp.weixin.qq.com 注册（个人主体即可），在「开发管理 → 开发设置」里找到 **AppID**。
2. **导入项目**：打开「微信开发者工具」，选「导入」，目录选本文件夹，AppID 填你自己的（不要用测试号，测试号不支持云开发）。
3. **开通云开发**：点工具栏的「云开发」按钮，按提示开通一个环境（先选免费的就行）。
4. **建数据库集合**：在云开发控制台进入「数据库」，新建下面的集合。**每个集合的「数据权限」都设为「仅管理端可读写」**（控制台里可能叫「所有用户不可读写」）。

   | 集合 | 用途 |
   |---|---|
   | `matches` | 比赛记录 |
   | `players` | 球员名单和个人资料 |
   | `draws` | 活动 / 签表 |
   | `signups` | 报名 |
   | `verified` | 管理员更正日常比分的标记、升级前旧记录的快照 |
   | `confirms` | 活动比赛的赛果确认 |
   | `requests` | 改分 / 退赛申请，以及所有留档：改分、撤销、删除活动、发起人和管理员的处理记录 |
   | `members` | 成员资格 |
   | `invites` | 邀请码 |
   | `reviews`、`bios`、`event_photos` | 已下线功能（对手评价、个人简介、活动相册）的旧数据，小程序端不再使用；新环境可以建成空集合 |
   | `event_contacts` | 活动联系人（已停用，可以删除） |

   ⚠️ **不要**把任何集合设成「所有用户可读」或「仅创建者可读写」。小程序端不直接访问数据库，所有读写都经过云函数 `tennis`：先校验成员资格，再按业务规则校验每个字段。只要有一个集合对前端开放，这些校验就能被绕过。
   完整的权限和部署说明见 `docs/项目进度.md`。
4.1 **部署云函数**：在开发者工具左侧找到 `cloudfunctions/tennis`，右键 →「上传并部署：云端安装依赖」。
   部署完成后，云开发控制台「云函数」里能看到 `tennis`。
   **云函数超时**：在云开发控制台「云函数 → tennis → 版本与配置 → 配置」里，把超时时间改成 **10 秒**（默认 3 秒）。
   **管理员**：在同一页的「环境变量」里添加 `ADMIN_OPENIDS`，值为管理员的 openid（多个用英文逗号分隔），见下面「仅限内部球友 → 升级步骤」第 4 条。
4.2 **隐私指引**：在公众平台「设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引」里，勾选「位置信息（选择位置）」并说明用途，
   比如「创建球友活动时在地图上选择球场位置」。否则真机上「在地图上选择」会失败。小程序端已经不上传照片，不需要勾选相册和摄像头。
5. 如果你有**多个**云环境，在 `app.js` 第 3 行填上环境 ID；只有一个环境的话留空即可。
6. 点「编译」就能用了。点「预览」用手机扫码测试，可以找两台手机分别录入，看是否同步。

## 给球友用

- **最省事**：在开发者工具里点「上传」，然后在公众平台「版本管理」中把它设为**体验版**，再在「成员管理」里把球友加为体验成员。
- **正式发布**：提交审核，类目选「工具 → 记账/效率」一类。`sitemap.json` 已设置为不被微信搜索收录，只有分享出去的人能打开。

### 云存储权限

小程序端只上传球员照片（`avatars/<用户 ID>/`，云函数 `setPhoto` 会再校验目录必须是本人的）。以前的活动照片还在 `event-photos/<活动 ID>/<上传者 ID>/` 里。客户端上传只进入 `avatars/`；服务端复制至 `player-photos/<用户 ID>/` 后检测，发布也使用这份快照，避免用户覆盖已检测文件。`player-photos/` 必须禁止客户端直接读写，链接只经云函数 `photoUrls` 发放（列表头像默认发服务端缩出的 320×320 缩略图 `<快照名>-s.jpg`，也在这个目录里；小程序端把缩略图存在本机 `USER_DATA_PATH/pl/`）。请使用以下自定义规则，不能仅选择「仅创建者可读写」：

```json
{
  "read": "resource.openid == auth.openid && (/^avatars\\//.test(resource.path) || /^event-photos\\//.test(resource.path))",
  "write": "resource.openid == auth.openid && (/^avatars\\//.test(resource.path) || /^event-photos\\//.test(resource.path))"
}
```

## 身份与权限

- 所有权限都按**用户 ID**（微信 openid，系统写入的 `_openid`，前端改不了）判断：报名、比赛双方、录分、改分、赛果确认。昵称只用于展示。
- **改昵称**：历史比赛、排名都跟着账号走，显示为新昵称。旧昵称保留给本人，别人不能再用。
- **同名**：如果有两个账号用了同一个昵称（比如有人绕过界面直接改数据库），这个昵称不对应任何账号，谁也拿不到对方的权限。
- **新记录**：比赛记录 `aIds / bIds`，报名记录 `partnerId`，活动 `uidOf`。活动比赛的双方由云函数根据报名记录重新计算，不信任比赛记录里写的 ID。
- **旧记录**：在加入用户 ID 之前录的比赛没有 ID，照常显示在战绩和统计里，但不会只凭昵称自动绑定账号，所以参赛者本人不能直接改分或确认；需要改时由管理员更正。
- **管理员**：只来自云函数环境变量 `ADMIN_OPENIDS`。权限范围见下面「仅限内部球友 → 成员管理」。

## 常见问题

- **保存失败 / 列表一直是空的**：通常是没开通云开发、集合名拼错，或者 AppID 用的是测试号。
- **删不掉别人录的记录**：这是权限设计的。管理员可以在这场比赛的详情里「撤销这场赛果」（会留档）。
- **改规则细节**：都在 `utils/rules.js` 里，例如抢七目标分是 `TB_TO = 7`。

## 正式战绩（避免两套战绩）

只有一套比赛记录（`matches` 集合），按下面的规则决定哪些计入战绩、排名和水平分（`utils/official.js`）：

- **活动比赛**：只能从签表 / 赛程录分，由云函数 `recordEventMatch` 校验对阵、本场赛制后写入；每一场固定一条记录（改比分是覆盖）。
  有人绕过签表直接往数据库写活动比分（这种记录一定带 `_openid`）：不展示、不计入。
- **日常比赛**：有一个人录了就计入，不需要对手确认。只有参赛者本人能录（云函数按用户 ID 校验），修改只能经云函数。
  以前「对手确认后才计入」的规则已取消，当时还在待确认的记录也一并计入。
- **弃权、中途退赛、轮空**：和正常完赛分开，不计入场数、胜率、排名和水平分。

**改了 `utils/rules.js`、`utils/draw.js`、`utils/event.js` 或 `utils/official.js` 之后**，要运行 `scripts/sync-shared.sh`，
把它们同步到 `cloudfunctions/tennis/shared/`，再重新部署云函数 `tennis`（云函数要用同一套规则校验比分）。

## 我的活动、待办、比分纠错、退赛弃权

- **我的活动**：「活动」页可以切换「全部活动 / 我的活动」，后者只列我发起、报名、参赛的活动，并标出「我发起 / 已报名 / 参赛中 / 已结束」。
- **我的待办**（「我的」页入口）：下一场比赛（活动、对手、阶段、场地、开赛时间，没安排显示「待安排」）、待我确认的活动比分、改分申请、退赛申请（发起人）、等待对方处理。日常比赛不需要确认，不进待办。
  全部实时计算，处理完、取消或失效的事项自动消失。只做小程序内待办，不发订阅消息。
- **比分纠错**：
  - 日常比赛：录入人和参赛者都可以直接改，改完立即生效。
  - 活动比赛对方还没确认：参赛球员或发起人在赛程里重新录。
  - 比分已锁定（活动比赛双方确认过、管理员更正过，以及旧规则下双方确认过的日常比赛）：参赛者只能在比赛详情里「申请修改比分」（填正确比分和原因，自动沿用本场赛制）。对方同意才生效，拒绝则保留原比分。
    活动比赛也可以由发起人裁定（必须填原因）；日常比赛没有发起人，对方不处理时找管理员更正。
  - 申请处理前，正式战绩、排名、晋级都不变。同一场同时只能有一条待处理申请；重复点击、两人同时处理都只生效一次；比分在申请后又变了，申请自动失效。
  - **管理员更正**：管理员可以在任何一场比赛的详情里「更正比分」（日常比赛和活动比赛的正常比分），不用填原因，直接生效并锁定；这场待处理的改分申请随之失效。弃权 / 退赛的场次不能更正，只能撤销。
  - **撤销赛果**：日常比赛只有录入人能撤销，已锁定的不能撤销；活动比赛里，参赛的录入人只能撤销「未确认、不影响后续场次」的正常比分，其他情况由发起人撤销（必须填原因）。管理员可以撤销任何一场，不用填原因。
  - 改动会推翻后续已录分的比赛时：普通用户被拦下；发起人先看到影响清单，确认并填写原因后才执行；管理员先看到影响清单，确认后执行。被推翻的比分作废，快照写进处理记录。后续还没录分的场次自动重排。
  - **比分修改记录**：比赛详情里列出这场比分的每次修改（谁、什么时候、从多少改成多少）；申请和裁定时填的原因不显示。
  - **留档**：每次改分（直接改、重新录、申请通过、裁定、管理员更正）和撤销，都把操作人、改前改后的比分、原因（如果有）和时间保存在 `requests` 里。
- **退赛、弃权、轮空**：
  - 报名阶段：直接「取消报名」，报名人数同步更新。
  - 签表生成后：球员在活动详情里「申请退赛」，由发起人处理；发起人也可以直接「登记球员退赛 / 缺席」。不会删除参赛者，签表不乱。
  - 赛前弃权：发起人在这一场的录分页「判赛前弃权」，另一方晋级，标「弃权胜 / 弃权负」，不填局分。
  - 中途退赛：发起人「记录中途退赛」，保留实际已打的局分，标出退赛方和原因。
  - 轮空：签表上显示「轮空晋级」，不生成对手和比分记录。
  - 小组赛退赛必须由发起人明确选一种处理方式：
    ① 已赛成绩保留，未赛场次判对手弃权胜；② 取消该球员全部小组成绩（含已打的）。两种情况下退赛者都排在最后、不能出线，由下一名递补。
  - 淘汰赛退赛：TA 的下一场（对手确定后）自动判对手弃权胜。
  - 弃权、中途退赛、轮空和正常完赛分开统计：不计入完赛场数、胜率、排名和水平分；晋级按处理结果执行。所有处理都记录操作者、原因和时间。

## 仅限内部球友（成员准入）

不是正式成员的人，即使拿到二维码或分享链接，也只能看到准入页（「私人网球活动管理」），看不到任何活动、报名、球员资料、战绩和排名。

**工作方式**
- 所有集合在控制台都设为「仅管理端可读写」，小程序端不能直接读写数据库。页面读取数据经过云函数 `tennis` 的数据网关（`data` 操作），先校验成员资格。写入只开放两种（新增自己参加的日常比赛、新增只有名字的球员），报名、个人资料、活动、改分、撤销比分都走专门的云函数操作，由服务端逐个字段校验。
- 云函数的每个操作都会重新查一次成员资格（不缓存），只有「查状态 / 申请加入 / 接受邀请」三项对非成员开放。
- 小程序启动、回到前台，以及任何请求被拒时，都会重新校验：不是正式成员就清掉本机缓存的活动、战绩等数据，跳到准入页。本机缓存只在最近 24 小时内确认过成员身份时才显示。

**状态**：未申请 → 申请（待审核）→ 正式成员 / 申请未通过（显示原因，可重新申请）；正式成员被移除后显示「成员资格已取消」和原因。有邀请码的可以在准入页直接输入加入，不需要审核。

**成员管理**（「我的」页，仅管理员可见）：审核申请（拒绝要填原因）、移除成员（要填原因，立即生效，不删除历史比分和记录，可以恢复）、生成一次性邀请（7 天有效，可以发链接或邀请码）、导入历史球友、核对报名数据；成员列表显示性别，没选性别的成员可以由管理员补选。

**管理员的权限**（都会留档）：
- 编辑任何活动的信息（名称、时间、场地）；删除活动（必须填原因）。
- 更正任何一场的正常比分、撤销任何一场比赛（不用填原因）。
- 替成员补选或更正性别。
- 生成签表、判弃权 / 退赛、裁定改分申请、处理退赛申请、单场安排仍然只有活动发起人能做。

### 升级步骤

1. **新建集合** `members`、`invites`，权限都设为「仅管理端可读写」。
2. **把所有已有集合改成「仅管理端可读写」**：`matches`、`players`、`draws`、`signups`、`verified`（以及之前已经是这个权限的 `confirms`、`reviews`、`event_contacts`、`bios`、`event_photos`、`requests`）。
3. **云存储安全规则**按上面「云存储权限」设置（只有本人能直接读写自己的文件）。
4. **配置第一位管理员**：
   - 先用管理员的微信打开小程序（会显示准入页），在开发者工具「调试器 → Console」或云开发控制台「云函数 → tennis → 日志」里找到这次调用的 OPENID；
     也可以在准入页提交一次申请，再到「数据库 → members」里看到这条记录的 `_id`，就是 openid（设为管理员后，这条申请记录不影响使用，「成员管理」里会把 TA 显示为管理员）。
   - 在云开发控制台「云函数 → tennis → 版本与配置 → 配置 → 环境变量」里添加 `ADMIN_OPENIDS`，值为管理员的 openid（多个用英文逗号分隔），保存。
   - 管理员不能在小程序里设置或取消，只能改这个环境变量。
5. 运行 `scripts/sync-shared.sh`，重新部署云函数 `tennis`，重新编译并上传小程序。
6. **初始化现有球友**：管理员打开「我的 → 成员管理 → 历史球友」，逐个确认是内部球友后勾选「导入」。不会自动把所有访问过的人设为成员；新球友用「邀请」链接或自己申请。
