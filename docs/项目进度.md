> **2026-11-17 照片检测修复（已部署）**：有成员上传照片后一直停在「检测中」，只有本人看得到，其他球友看不到（`avatar_checks` 状态 `checking`、`players` 没有 `photo`）。原因：检测结果推送比云函数写检测记录先到时，云函数只等约 3 秒就回复「已收到」，结果丢失；也没有超时兜底，微信漏推时同样永远停在检测中。修复：① 推送先到时把结果暂存为 `avatar_checks` 的 `early-<trace_id>`，`setPhoto` 写完记录后接着处理；② 检测中超过 1 小时没结果的，本人打开小程序或资料页时判为「检测出错」（`timedOut: true`），删掉检测副本，提示重新上传，晚到的结果不再生效。只改云函数，重新部署 `tennis` 即可，不用重新提审小程序。已经卡住的成员：部署后打开资料页会看到「检测出错，请重新上传」，重新上传一次即可。

## 一、已完成功能

### 账号与成员准入
- **身份**：一律使用云端获取的 openid（用户 ID），昵称只用于展示。
  - 改昵称不影响历史战绩、报名和评价，旧昵称保留给本人。
  - 两个账号同名时，这个名字不绑定任何人。
- **成员准入**：不是正式成员只能看到准入页「私人网球活动管理」（`pages/gate`）。
  - 状态流转：未申请 → 待审核 → 正式成员 / 申请未通过 / 成员资格已取消，每种状态都显示原因和下一步。
  - 支持一次性邀请（7 天有效）：可以发邀请链接，也可以把邀请码发给对方。准入页默认就是「用邀请码加入」（填邀请码和称呼，按钮「验证并进入」；原来的「加入球友圈」带社交圈子意味，2026-11-19 未过审核后改掉）；没有邀请码的人点「没有邀请码？提交申请，等管理员审核」改为提交申请。邀请码有效就直接成为正式成员并进入小程序，不需要管理员审核；已经提交过申请、还在等审核的人也可以在准入页输入邀请码直接加入。昵称必填（最多 10 个字；已提交过申请的人可以不再填，沿用申请时的昵称；没填不占用邀请码），输入框提示「你的昵称」（2026-11-20 由「称呼」改名）：第一次设置个人资料时昵称会预填这个昵称（可以改，保存时照常检测内容和重名），以后在资料里改昵称，成员名单里的昵称也跟着改。从别的页面（例如分享的活动链接）被拦到准入页的，加入后回到原页面，参数一起带上。提交微信审核时，把邀请码写进审核备注：邀请码一次性，审核员可能不止一个人，备注里写 2～3 个、有效期设长一些（最多 30 天）；审核通过后在成员管理里移除审核员的账号。
- **成员管理**（`pages/members`，仅管理员）：审核申请、移除 / 恢复成员、生成邀请、导入历史球友；成员列表显示性别，没选性别的成员可以由管理员补选（留档）。
  - 管理员由云函数环境变量 `ADMIN_OPENIDS` 配置。
  - 新申请提示：有待审核的加入申请时，管理员打开小程序会在底部「我的」看到红点，「成员管理」入口显示待审核人数（`memberStatus` 带回 `pendingApply`）。只是小程序内提示，不发微信消息。
  - 活动权限：管理员可以编辑任何活动的信息（手动名称、时间、场地编号、地图坐标）和删除活动（必须填原因），都会留档；管理员还可以直接更正任何一场的比分、撤销任何一场比赛（不用填原因，留档）。生成签表、判弃权 / 退赛、裁定改分申请、处理退赛、单场安排仍然只有发起人能做。
- **资格校验**：每次云函数调用都实时校验。前端在启动、回到前台、请求被拒时清除受保护的缓存，并跳转到准入页。

### 球员资料与主页
- **资料编辑**：照片可从相册选或拍照（1:1 裁剪预览）；另有昵称、性别、自评等级、个人简介（必须通过内容安全检测）。
- **球员主页**：「我的」和别人的主页共用 `components/player-home`，内容包括：
  - 比赛等级与自评等级分开显示；
  - 排名、场数、胜负、胜率；
  - 近期比赛与全部历史；
  - 对手评价汇总；
  - 本人才能编辑。
- **头像**：数据库只存 fileID，链接由云函数校验成员资格后发放（30 分钟有效），加载失败显示默认头像。

### 活动
- **发布**：
  - 活动形式：小组赛、淘汰赛、小组赛＋淘汰赛（每组出线 1 或 2 名）。
  - 分阶段设置规则：4 / 6 局制、金球 / 占先、一盘 / 三盘两胜。淘汰赛规则可统一设置，也可按轮次设置。
  - 名称手动输入（必填、最多 20 个字），通过云端内容检测后保存。时间、场地编号、地图定位由固定选项或地图选点设置；地图只保留坐标。联系人功能已从小程序端删除（社交属性，个人主体过不了审核），云函数也不再读取、保存或返回联系人（`getContact` / `saveContact` 只是给旧版小程序留的空操作），`event_contacts` 集合可以在云开发控制台直接删除。
- **组别和名额**：活动可以设组别（男子 / 女子 / 混双），报名时按个人资料里的性别校验；淘汰赛名额是签数，小组赛可设报名上限，满了排进候补，按报名先后自动递补（不存状态，实时计算）。活动列表有日历视图。
- **报名**：开放报名，双打可带搭档（按 ID）。报名名单显示头像、昵称、性别、排名、场数、胜率、等级，点头像或昵称进入球员主页。
- **签表**：抽签带种子与轮空，小组蛇形分组，小组出线后自动交叉生成淘汰赛签表。
- **录分**：从签表或赛程点场次录分，自动带出双方和本场规则。
  - 由云函数校验后写入，每场固定一条记录。
  - 已双方确认的比分不能直接覆盖。
- **单场安排**：签表生成后，发起人可以在「赛程」里给每一场单独安排日期、时间和场地（例如「3 号场」），对阵还没确定的场次也能先排。
  - 赛程、录分页、待办的「下一场比赛」都会显示；没排的场次沿用活动的日期、时间和场地。
  - 重新生成签表后，原来的安排作废。
- **我的活动**：活动页可切换「全部 / 我的活动」。
- **活动相册**：
  - 发起人和报名球员可以上传，多选或拍照，上传前压缩，显示进度，失败可重试。
  - 微信异步图片审核（`mediaCheckAsync` + `wxa_media_check` 推送），通过后才对其他人公开。
  - 上传者只能删自己的照片，发起人可以管理全部照片。

### 战绩、确认、纠错、评价
- **正式战绩**（`utils/official.js`）：
  - 活动比赛只认云函数写入的记录。
  - 日常比赛录入后直接生效，不需要对手确认（以前待确认的记录也一并计入）。
  - 升级前的旧记录首次运行时自动迁移为正式战绩。
- **日常比赛**：从「战绩」页的次要入口记录。录入人固定在 A 方，对手必须是已注册球员。
- **比分纠错**：
  - 日常比赛：录入人和参赛者都可以直接修改，改完立即生效；活动比赛在对方确认前可以直接重录。每次改分都留档（`requests` 里 `type: 'edit'`：操作人、改前改后的比分），比赛详情里显示「比分修改记录」（`matchState` 带 `detail` 时返回 `changes`，不含原因）。
  - 已锁定的比分（双方确认过、管理员更正过）只能提交申请，对方同意或拒绝；活动比赛可由发起人裁定（须填原因），日常比赛不能单方面裁定。
  - 防重复提交、防并发处理，申请提交后比分又变了则申请失效。
  - 若会推翻后续已录分的场次，必须由发起人确认影响后执行，被推翻的记录作废并留档。
- **退赛 / 弃权 / 轮空**：
  - 报名阶段可以直接取消报名；签表生成后由球员申请、发起人处理。
  - 赛前弃权不填局分；中途退赛保留实际已打的局分。
  - 小组赛退赛必须明确选择处理方式：「已赛保留、未赛判弃权」或「成绩全部取消」。
  - 淘汰赛退赛后，下一场自动判对手弃权胜。
  - 弃权、退赛、轮空不计入完赛统计，也不开放互评。
- **待办**（`pages/todo`）：下一场比赛、待我确认 / 等待对方（只有活动比赛，确认只用来锁定比分；日常比赛不需要确认）、改分申请、退赛申请。对手互评已删除，没有「待评价」。
- **水平分**：按得局率计算，含防炸鱼；挑战书限制低打高。

  - 爆冷：赛前比赛等级比对手低 0.3 以上还赢了；有人还在定级期（前 5 场）的比赛不算。终结连胜：对手赛前至少 3 连胜。

  - 冠军按活动决赛的比赛记录认定（弃权胜也算）；只有小组赛的活动没有决赛，不产生冠军。

## 二、数据库与存储权限（必须保持）

**所有集合都设为「仅管理端可读写」**（控制台里可能叫「所有用户不可读写」）。小程序端不直接访问数据库，一律经云函数 `tennis` 的数据网关（`data` 操作）。

| 集合 | 用途 |
|---|---|
| matches | 比赛记录 |
| players | 球员 / 个人资料 |
| draws | 活动 |
| signups | 报名 |
| verified | 正式战绩快照（含旧记录迁移标记） |
| confirms | 赛果确认 |
| reviews | 对手评价 |
| event_contacts | 活动联系人（已停用，可以删除） |
| bios | 个人简介 |
| event_photos | 活动照片（fileID、审核状态） |
| requests | 改分 / 退赛申请及处理记录 |
| members | 成员资格 |
| invites | 邀请码 |
| follows | 关注关系（只公开人数） |
| rackets | 我的球拍：球拍档案（`owner`、自动编号 `no`；索引 `owner` + `no`） |
| racket_logs | 我的球拍：穿线 / 维护记录（`owner`、`racketId`、`kind`；索引 `owner` + `racketId` + `date`） |
| growth_matches | 成长档案的私人比赛记录（`owner` = 本人用户 ID，只由云函数写入；不在网关白名单里，只经 `growth*` 操作按本人读写；索引 `owner` + `date`） |

**数据网关的写权限**（`GW_OPS`）：
- 网关只允许两种写入：`matches` 新增日常比赛，`players` 新增「只有名字」的球员。其他写入都走专门的云函数操作。
- `players` 本人资料只能经 `saveProfile` 写入：服务端检查昵称不和别人重复（包括别人以前用过的昵称），照片只认本人 `avatars/<用户 ID>/` 目录。
- `draws` 只能经 `createDraw` / `generateDraw` / `updateDrawInfo` / `removeDraw` / `setFixtureSlot`（单场安排，只有发起人）写入，服务端逐个字段校验。`withdrawals` 只能由退赛流程写入。参赛名 → 用户 ID（`uidOf`）只接受报名记录或该账号当前资料能证明的对应。已经录分或登记过退赛的活动不能重新生成签表。删除活动是软删除：签表不再显示，联系人删除，活动相册的照片文件和记录删除，未处理的申请作废，已录比分保留。照片文件删除失败的，fileID 记在 `requests` 的删除记录里（`type: 'deleteDraw'`），需要在控制台手动清理。
- `signups` 只能经云函数 `signUp` / `cancelSignup` 写入。参赛名取本人资料里的昵称，搭档按用户 ID 校验，与其他球友重名时拒绝报名。签表生成后不能直接取消报名。
- `matches` 只允许新增日常比赛，而且只有管理员能录，而且管理员本人必须参赛（按用户 ID）；普通成员不能新增日常比赛。修改走 `editMatchScore` 或改分申请，删除走 `revokeMatch`。管理员可以在比赛详情里「更正比分」（`adminFixScore`，日常比赛和活动比赛都可以）：不用填原因，直接生效并留档（操作人、改前改后的比分），更正后比分锁定，待处理的改分申请随之失效；活动比赛会推翻后续已录分场次时，先列出影响，确认后才执行。
- `revokeMatch`：日常比赛只有录入人能撤销，已锁定的比分不能撤销。活动比赛中，参赛的录入人只能撤销「未确认、不影响后续场次」的正常比分；其他情况只有发起人能撤销，必须填原因，受影响的场次一并作废。管理员可以撤销任何一场（不用填原因，影响后续场次时先确认）。所有撤销都会写入 `requests` 留档（`type: 'revoke'`，管理员撤销带 `byAdmin`）。

**云存储安全规则**：
```json
{
  "read": "resource.openid == auth.openid && (/^avatars\\//.test(resource.path) || /^event-photos\\//.test(resource.path))",
  "write": "resource.openid == auth.openid && (/^avatars\\//.test(resource.path) || /^event-photos\\//.test(resource.path))"
}
```
存储目录：`avatars/<用户 ID>/`、`event-photos/<活动 ID>/<上传者 ID>/`。

## 三、部署要求

1. 修改 `utils/rules.js`、`utils/draw.js`、`utils/event.js`、`utils/official.js`、`utils/growth.js`、`utils/racket.js` 之后，先运行 `scripts/sync-shared.sh`。
2. 部署云函数：在开发者工具里右键 `cloudfunctions/tennis` →「上传并部署：云端安装依赖」。
3. 云函数配置（云开发控制台 → 云函数 → tennis → 版本与配置）：
   - 超时时间：10 秒；
   - 环境变量 `ADMIN_OPENIDS`：管理员 openid，多个用英文逗号分隔；
   - `config.json` 已声明 openapi 权限：`security.msgSecCheck`、`security.mediaCheckAsync`。
4. 消息推送：云开发控制台 → 设置 → 全局设置 → 消息推送，添加 `event` / `wxa_media_check` → 云函数 `tennis`。
5. 数据库新建集合 `follows`（关注）、`growth_matches`（成长档案）、`rackets`、`racket_logs`（我的球拍），权限设为「仅管理端可读写」；索引：`growth_matches` 为 `owner` 升序 + `date` 降序，`rackets` 为 `owner` 升序 + `no` 升序，`racket_logs` 为 `owner` 升序 + `racketId` 升序 + `date` 降序。
6. 不需要配置订阅消息模板，也不需要配置 downloadFile 合法域名（这两项功能已移除）。
7. 用户隐私保护指引需要声明：选中的照片或视频信息、摄像头、位置信息（选择位置）。`app.json` 已声明 `chooseLocation`。
8. 首次升级到成员准入版本后：管理员打开「成员管理 → 历史球友」，逐个确认后导入。
9. 重新编译，上传体验版，并在「成员管理」里添加体验成员。

## 五、已知问题与限制

- **已发出的照片收不回**：已下载的照片无法远程收回；已发出的临时链接在过期前（最长 30 分钟）仍可能打开。
- **非成员仍能上传文件**：云存储规则无法判断成员资格，未批准用户理论上能上传文件，但文件不会被登记、展示或被他人读取。
- **缓存短暂可见**：被移除的成员重新打开小程序时，在资格校验返回前（约数百毫秒）可能短暂看到 24 小时内的本机缓存。
- **云函数费用**：所有数据读取都经过云函数。已做的优化：分页改为每页 100 条；前端内存缓存 60 秒，并合并同时发起的相同请求（切换 tab 不再重复拉取）；待办、待确认、可评价列表改为批量查询。缓存带来的代价是：别人新录的比分，最多要 60 秒或下拉刷新后才能看到。
- **签表名字是快照**：改名后，签表里仍显示生成签表时的参赛名；照片和关联按 ID 更新。
- **同名账号**：统计已按用户 ID 分开。旧记录（没有 ID）的名字如果同时被两个账号使用，这些旧记录单独统计，不算到任何一个账号上。
- **旧数据未绑定账号**：升级前的旧比赛没有用户 ID，只显示和统计，不能确认或评价。
- **基础库版本要求**：`cropImage`、`compressImage` 的尺寸参数需要 2.26.0 及以上，`virtualHost` 需要 2.11.2，可编辑的 `showModal` 需要 2.17.1。
- **旧报名记录未清洗**：本次修复前经网关写入的报名记录，名字是客户端填的。如果怀疑有冒名报名，需要人工核对 `signups` 里 `name` 和 `_openid` 是否对应。
