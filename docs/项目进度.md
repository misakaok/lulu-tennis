# LULU网球 · 项目进度

更新时间：2026-11-10
形态：微信小程序 + 微信云开发（单个云函数 `tennis`），仅限内部球友使用。

## 一、已完成功能

### 账号与成员准入
- **身份**：一律使用云端获取的 openid（用户 ID），昵称只用于展示。
  - 改昵称不影响历史战绩、报名和评价，旧昵称保留给本人。
  - 两个账号同名时，这个名字不绑定任何人。
- **成员准入**：不是正式成员只能看到「仅限内部球友使用」页（`pages/gate`）。
  - 状态流转：未申请 → 待审核 → 正式成员 / 申请未通过 / 成员资格已取消，每种状态都显示原因和下一步。
  - 支持一次性邀请链接（7 天有效）。
- **成员管理**（`pages/members`，仅管理员）：审核申请、移除 / 恢复成员、生成邀请、导入历史球友。
  - 管理员由云函数环境变量 `ADMIN_OPENIDS` 配置。
  - 赛事权限：管理员可以编辑任何赛事的信息（名称、时间、场地、联系人）和删除赛事（必须填原因），都会留档；生成签表、录分、裁定改分、处理退赛、单场安排仍然只有发起人能做。
- **资格校验**：每次云函数调用都实时校验。前端在启动、回到前台、请求被拒时清除受保护的缓存，并跳转到准入页。

### 球员资料与主页
- **资料编辑**：照片可从相册选、拍照（1:1 裁剪预览）或用微信头像；另有昵称、性别、自评等级、个人简介（必须通过内容安全检测）。
- **球员主页**：「我的」和别人的主页共用 `components/player-home`，内容包括：
  - 比赛等级与自评等级分开显示；
  - 排名、场数、胜负、胜率；
  - 近期比赛与全部历史；
  - 对手评价汇总；
  - 本人才能编辑。
- **头像**：数据库只存 fileID，链接由云函数校验成员资格后发放（30 分钟有效），加载失败显示默认头像。

### 赛事
- **发布**：
  - 赛事形式：小组赛、淘汰赛、小组赛＋淘汰赛（每组出线 1 或 2 名）。
  - 分阶段设置规则：4 / 6 局制、金球 / 占先、一盘 / 三盘两胜。淘汰赛规则可统一设置，也可按轮次设置。
  - 时间、场地名称、地图定位、联系人（不用填街道地址）。联系人按可见范围由云函数返回。
- **报名**：开放报名，双打可带搭档（按 ID）。报名名单显示头像、昵称、性别、排名、场数、胜率、等级，点头像或昵称进入球员主页。
- **签表**：抽签带种子与轮空，小组蛇形分组，小组出线后自动交叉生成淘汰赛签表。
- **录分**：从签表或赛程点场次录分，自动带出双方和本场规则。
  - 由云函数校验后写入，每场固定一条记录。
  - 已双方确认的比分不能直接覆盖。
- **单场安排**：签表生成后，发起人可以在「赛程」里给每一场单独安排日期、时间和场地（例如「3 号场」），对阵还没确定的场次也能先排。
  - 赛程、录分页、待办的「下一场比赛」都会显示；没排的场次沿用赛事的日期、时间和场地。
  - 重新生成签表后，原来的安排作废。
- **我的赛事**：赛事页可切换「全部 / 我的赛事」。
- **赛事相册**：
  - 发起人和报名球员可以上传，多选或拍照，上传前压缩，显示进度，失败可重试。
  - 微信异步图片审核（`mediaCheckAsync` + `wxa_media_check` 推送），通过后才对其他人公开。
  - 上传者只能删自己的照片，发起人可以管理全部照片。

### 战绩、确认、纠错、评价
- **正式战绩**（`utils/official.js`）：
  - 赛事比赛只认云函数写入的记录。
  - 日常比赛须对手确认，确认后写入 `verified` 快照。
  - 升级前的旧记录首次运行时自动迁移为正式战绩。
- **日常比赛**：从「战绩」页的次要入口记录。录入人固定在 A 方，对手必须是已注册球员。
- **比分纠错**：
  - 对方确认前，录入方可以直接修改。
  - 确认后只能提交申请，对方同意或拒绝；赛事比赛可由发起人裁定（须填原因），日常比赛不能单方面裁定。
  - 防重复提交、防并发处理，申请提交后比分又变了则申请失效。
  - 若会推翻后续已录分的场次，必须由发起人确认影响后执行，被推翻的记录作废并留档。
- **退赛 / 弃权 / 轮空**：
  - 报名阶段可以直接取消报名；签表生成后由球员申请、发起人处理。
  - 赛前弃权不填局分；中途退赛保留实际已打的局分。
  - 小组赛退赛必须明确选择处理方式：「已赛保留、未赛判弃权」或「成绩全部取消」。
  - 淘汰赛退赛后，下一场自动判对手弃权胜。
  - 弃权、退赛、轮空不计入完赛统计，也不开放互评。
- **对手互评**：三个维度各 1～5 分，可附文字（须通过内容安全检测）。只有实际交手、比分双方确认的对立双方可以互评，不能重复评价，匿名汇总展示，不影响等级。
- **待办**（`pages/todo`）：下一场比赛、待我确认、等待对方、改分申请、退赛申请、待评价。
- **水平分**：按得局率计算，含防炸鱼；挑战书限制低打高。

### 关注、赛季、生涯成就（2026-11-10）
- **关注**：在球员主页点「＋ 关注」。
  - 「我的」主页显示「关注 N · 粉丝 N」，点进去是「我的关注」：关注的球友（等级、排名、本赛季战绩）和他们最近的正式比赛。
  - 排行榜可以切换「只看关注」。
  - 只公开人数：别人看不到你关注了谁、谁关注了你。最多关注 200 人。
- **赛季**：按比赛日期的自然年划分（2026 赛季 = 2026 年全年）。
  - 排行榜可以切换「生涯 / 某个赛季」，胜负和胜率只算这个赛季；水平分不分赛季，始终连续计算。
  - 球员主页有「赛季战绩」表：每个赛季的场数、胜负、胜率、冠军数。
- **生涯成就**：球员主页的「生涯成就」卡片，全部由正式战绩自动计算。
  - 数据：冠军、决赛次数、参加赛事数、最长连胜、当前连胜、最高等级、单打 / 双打战绩、老对手、首场比赛。
  - 15 个徽章（初登场、首胜、10 / 50 / 100 场、3 / 5 / 10 连胜、决赛选手、冠军、三冠王、赛事达人、送蛋、逆转、单双全能），没达成的显示进度。
  - 冠军按赛事决赛的比赛记录认定（弃权胜也算）；只有小组赛的赛事没有决赛，不产生冠军。

### 统计、读取优化、数据核对（2026-11-10）
- **减少云函数调用**：赛事详情页 8～9 次调用合成 1 次（`drawDetail`）；「我的赛事」2～4 次合成 1 次（`mySignups`）；战绩内容没变时云函数只回「没变」，不再下发整份数据；比赛详情页少读 1 次。
- **统计按用户 ID**：两个账号同名时统计也分开，不再显示「统计暂不可用」。没有同名冲突时，结果和以前完全一样（已用 300 场随机数据对比）。
- **一次性读取**：读战绩从约 9 次云函数调用降到 1 次（云函数 `dataset`）。
- **报名数据核对**：「成员管理 → 数据核对」，列出名字和账号对不上的旧报名记录，只检查、不修改。
- **成员列表**：同时显示资料昵称和申请时填的称呼；每一行可以复制用户 ID。

## 二、数据库与存储权限（必须保持）

**所有集合都设为「仅管理端可读写」**（控制台里可能叫「所有用户不可读写」）。小程序端不直接访问数据库，一律经云函数 `tennis` 的数据网关（`data` 操作）。

| 集合 | 用途 |
|---|---|
| matches | 比赛记录 |
| players | 球员 / 个人资料 |
| draws | 赛事 |
| signups | 报名 |
| verified | 正式战绩快照（含旧记录迁移标记） |
| confirms | 赛果确认 |
| reviews | 对手评价 |
| event_contacts | 赛事联系人 |
| bios | 个人简介 |
| event_photos | 赛事照片（fileID、审核状态） |
| requests | 改分 / 退赛申请及处理记录 |
| members | 成员资格 |
| invites | 邀请码 |
| follows | 关注关系（只公开人数） |

**数据网关的写权限**（`GW_OPS`）：
- 网关只允许两种写入：`matches` 新增日常比赛，`players` 新增「只有名字」的球员。其他写入都走专门的云函数操作。
- `players` 本人资料只能经 `saveProfile` 写入：服务端检查昵称不和别人重复（包括别人以前用过的昵称），照片只认本人 `avatars/<用户 ID>/` 目录。
- `draws` 只能经 `createDraw` / `generateDraw` / `updateDrawInfo` / `removeDraw` / `setFixtureSlot`（单场安排，只有发起人）写入，服务端逐个字段校验。`withdrawals` 只能由退赛流程写入。参赛名 → 用户 ID（`uidOf`）只接受报名记录或该账号当前资料能证明的对应。已经录分或登记过退赛的赛事不能重新生成签表。删除赛事是软删除：签表不再显示，联系人删除，赛事相册的照片文件和记录删除，未处理的申请作废，已录比分保留。照片文件删除失败的，fileID 记在 `requests` 的删除记录里（`type: 'deleteDraw'`），需要在控制台手动清理。
- `signups` 只能经云函数 `signUp` / `cancelSignup` 写入。参赛名取本人资料里的昵称，搭档按用户 ID 校验，与其他球友重名时拒绝报名。签表生成后不能直接取消报名。
- `matches` 只允许新增日常比赛。修改走 `editMatchScore` 或改分申请，删除走 `revokeMatch`。
- `revokeMatch`：日常比赛只有录入人能撤销，而且必须在对方确认前。赛事比赛中，参赛的录入人只能撤销「未确认、不影响后续场次」的正常比分；其他情况只有发起人能撤销，必须填原因，受影响的场次一并作废。所有撤销都会写入 `requests` 留档（`type: 'revoke'`）。

**云存储安全规则**：
```json
{
  "read": "resource.openid == auth.openid",
  "write": "resource.openid == auth.openid && (/^avatars\\//.test(resource.path) || /^event-photos\\//.test(resource.path))"
}
```
存储目录：`avatars/<用户 ID>/`、`event-photos/<赛事 ID>/<上传者 ID>/`。

## 三、部署要求

1. 修改 `utils/rules.js`、`utils/draw.js`、`utils/event.js`、`utils/official.js` 之后，先运行 `scripts/sync-shared.sh`。
2. 部署云函数：在开发者工具里右键 `cloudfunctions/tennis` →「上传并部署：云端安装依赖」。
3. 云函数配置（云开发控制台 → 云函数 → tennis → 版本与配置）：
   - 超时时间：10 秒；
   - 环境变量 `ADMIN_OPENIDS`：管理员 openid，多个用英文逗号分隔；
   - `config.json` 已声明 openapi 权限：`security.msgSecCheck`、`security.mediaCheckAsync`。
4. 消息推送：云开发控制台 → 设置 → 全局设置 → 消息推送，添加 `event` / `wxa_media_check` → 云函数 `tennis`。
5. 数据库新建集合 `follows`（关注），权限设为「仅管理端可读写」。
6. 不需要配置订阅消息模板，也不需要配置 downloadFile 合法域名（这两项功能已移除）。
7. 用户隐私保护指引需要声明：选中的照片或视频信息、摄像头、位置信息（选择位置）。`app.json` 已声明 `chooseLocation`。
8. 首次升级到成员准入版本后：管理员打开「成员管理 → 历史球友」，逐个确认后导入。
9. 重新编译，上传体验版，并在「成员管理」里添加体验成员。

## 五、已知问题与限制

- **已发出的照片收不回**：已下载的照片无法远程收回；已发出的临时链接在过期前（最长 30 分钟）仍可能打开。
- **非成员仍能上传文件**：云存储规则无法判断成员资格，未批准用户理论上能上传文件，但文件不会被登记、展示或被他人读取。
- **缓存短暂可见**：被移除的成员重新打开小程序时，在资格校验返回前（约数百毫秒）可能短暂看到 24 小时内的本机缓存。
- **云函数费用**：所有数据读取都经过云函数。已做的优化：分页改为每页 100 条；前端内存缓存 60 秒，并合并同时发起的相同请求（切换 tab 不再重复拉取）；待办、待确认、可评价列表改为批量查询。缓存带来的代价是：别人新录的比分，最多要 60 秒或下拉刷新后才能看到。
- **签表名字是快照**：改名后，签表里仍显示生成签表时的参赛名；照片和关联按 ID 更新。
- **同名账号**：统计已按用户 ID 分开。旧记录（没有 ID）的名字如果同时被两个账号使用，这些旧记录单独统计，不算到任何一个账号上。
- **旧数据未绑定账号**：升级前的旧比赛没有用户 ID，只显示和统计，不能确认或评价。
- **基础库版本要求**：`cropImage`、`compressImage` 的尺寸参数需要 2.26.0 及以上，`virtualHost` 需要 2.11.2，可编辑的 `showModal` 需要 2.17.1。
- **旧报名记录未清洗**：本次修复前经网关写入的报名记录，名字是客户端填的。如果怀疑有冒名报名，需要人工核对 `signups` 里 `name` 和 `_openid` 是否对应。
