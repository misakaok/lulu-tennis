## 一、当前功能（2026-11-22 按代码核对）

> 本节只写现在小程序里有的功能。已删除 / 停用的见本节最后一条，变更经过见文件开头的记录。界面上的叫法按 `CLAUDE.md`「界面约定」（分组循环、单淘汰、对阵表、场次、最后一轮等）。

底部 5 个 tab：**活动、战绩、排行、球拍、我的**。

### 账号与成员准入
- **身份**：一律使用云端获取的 openid（用户 ID），昵称只用于展示；两个账号同名时，这个名字不绑定任何人。
- **准入页**（`pages/gate`，「私人网球活动管理」）：不是正式成员只能看到这一页。
  - 默认「用邀请码加入」：填邀请码和昵称（最多 10 个字，过内容检测，先检测再占用邀请码），有效就直接成为正式成员。邀请一次性，默认 7 天有效（最多 30 天），可以发邀请链接或邀请码，不带备注。
  - 没有邀请码的点「没有邀请码？提交申请，等管理员审核」；等审核的人也可以再输入邀请码直接加入。
  - 状态：未申请 → 待审核 → 正式成员 / 申请未通过 / 成员资格已取消，每种状态显示原因（固定选项）和下一步。
  - 从分享链接被拦到准入页的，加入后回到原页面，参数一起带上。
  - 第一次设置资料时预填准入昵称；之后改资料昵称，成员名单里的昵称也跟着改。
  - 用邀请码刚加入、还没设置资料的，直接进资料页（2026-11-22）：昵称已预填，性别必选，等级照常；保存后回到原来要去的页面（例如分享的活动），也可以点「稍后再设置」直接进小程序（不强制）。已经有资料的照常进入。
- **资格校验**：每次云函数调用实时校验；前端在启动、回到前台、请求被拒时清除受保护的缓存并跳转准入页。
- **提审**：邀请码写进审核备注（写 2～3 个、有效期设长），过审后在成员管理里移除审核员账号、作废没用完的邀请码。

### 活动（tab 1，`pages/draw` / `draw-view` / `draw-new` / `event-edit`）
- **首页顶部**：球场图作背景（`images/hero-court.jpg`，2026-11-22 加），标题、说明和「创建球友活动」按钮仍是页面组件，叠在图片左边。
- **界面配图（2026-11-22 起）**：卡片背景图由用户另外生成（需求页见 claude.ai 上的「LULU网球配图需求」），已全部接入：活动首页顶部、比赛详情记分牌（`bg-score.jpg`）、战绩页「我的战绩」卡（`bg-mine.jpg`）、活动详情顶部（`bg-event.jpg`）、球员卡（`bg-card.jpg`）、准入页（`bg-gate.jpg`）、成长档案（`bg-growth.jpg`），以及空状态插画（`art-ball` 通用、`art-net` 活动、`art-basket` 成长档案、`art-trophy` 排行榜；准入页标题上方也换成 `art-ball`）。场地颜色都统一提亮到原来渐变卡片的淡紫。第二批：分享卡片底图（`share-bg.jpg` / 固定封面 `share.jpg`）、球员主页「生涯成就」21 个徽章改成 3D 图标（`images/badges/<徽章 id>.png`，没达成的灰色变淡）。第三批：插画和徽章按统一风格重做，徽章是淡紫圆形章牌，同类等级（场数、连胜、冠军）用星星区分。
- **只有管理员能发布**：创建活动、修改活动信息、生成对阵都在云端校验 `ADMIN_OPENIDS`；生成对阵还要求是活动发起人。普通成员只能浏览、报名、取消报名，看不到创建 / 编辑 / 生成对阵入口，直接打开页面也会被拦。
- **活动信息**：
  - 比赛名称手动填（必填、最多 20 个字，默认「M月D日 内部赛」），云端 `msgSecCheck` 明确通过才保存。
  - 日期、时间；场地从 1～30 号场里选（可留空）；地图选点存坐标，地点名称和地址过内容检测后存 `draws.place`，详情页「地点」一行显示，导航也带上。没通过只存坐标并提示。
  - 创建时「地图定位」下面有「最近使用的地点」（`utils/places.js`）：从已有活动取最近 5 个有效地点（按创建时间从新到旧；相距 100 米以内算同一个地点只显示一次；只有坐标的「历史地图位置」最多显示 1 条；删除的和没坐标的不算），点一下直接填回坐标和地点名称，不打开地图；只有坐标的旧活动显示「历史地图位置」+ 活动日期；选了这种位置时表单提示可以补名称，点「地图定位」地图会停在这个位置，点一下球场名称就带回来，随新活动保存后下次就显示名称。场号单独选，不跟着带过来。保存照常走 `createDraw` 和地点文字检测。编辑页不显示。
  - 形式：分组循环、单淘汰、循环＋淘汰（每组前 1 或 2 名进入下一轮）；单打 / 双打。
  - 规则分阶段设置：4 / 6 局制、金球 / 占先、一盘 / 三盘两胜；单淘汰可以统一设置，也可以按轮次设置。
  - 组别：男子 / 女子 / 混双（混双只有双打），报名时按资料里的性别校验。
  - 建议水平（可选）：最低 – 最高两个下拉（选项同自评等级，可以只选一档），列表和详情显示「建议水平 2.5–3.0」，只作参考，不限制报名。
- **报名**：双打可以带搭档（按用户 ID）。名额按人数算（单淘汰是签数，分组循环可设上限），满了照样能报，排进候补，有人取消按报名先后自动递补（实时计算，不存状态）。活动详情显示「已报名 3/4 人 · 还差 1 人 / 已满 · 候补 2 人」（有人在候补时剩下的名额不算空位）；双打分组循环可以设「2 队」（4 人）。报名名单显示照片 / 首字圆、昵称、性别、排名、场数、胜率、等级，点进球员主页。
- **生成对阵**：
  - 种子设置：单打「种子选手」、双打「种子队伍」，可以按水平推荐；1、2 号种子分在上下半区，有种子时种子优先轮空。
  - 自动轮空，分组蛇形分配，分组循环结束后自动交叉生成淘汰对阵。
  - 已录分或登记过退赛的活动不能重新生成。
- **单场安排**：生成对阵后，发起人可以给每一场单独定日期、时间和场地（对阵没确定的场次也能先排），重新生成后作废；没排的沿用活动的安排。保存时如果同一天同一开打时间已经有别的未结束场次单独排了同一片场地（只比较单独排过的场地，沿用活动场地的不算）、或同一位球员（按账号，双打四位都查）同时在那一场，先弹窗列出那几场和原因，可以「返回修改」或「仍然保存」；只有活动开始时间、没定单场时间的不查。
- **活动比分**：从对阵表点场次录分，自动带出双方和本场规则；云函数写入，每场一条记录，一人录了就计入战绩。确认只用来锁定比分。
- **退赛 / 弃权**：对阵生成后由球员申请、发起人处理；赛前弃权不填局分，中途退赛保留已打的局分；分组循环退赛要选「已赛保留、未赛判弃权」或「成绩全部取消」；单淘汰退赛后下一场自动判对手弃权胜。退赛名单只显示状态和处理方式，不公开原因。
- **活动列表**：「全部活动 / 我的活动 / 我的下一场」三个选项卡，默认全部活动（日历视图已于 2026-11-22 移除）；卡片是台历式日期块 + 状态 + 形式 · 单双打 · 人数 · 种子数 + 我发起 / 已报名 / 参加中 / 参加过 + 进度或冠军。
- **我的下一场**（`utils/next-match.js`）：在首页已有的活动、战绩、我的报名上算出本人最近一场没结束的场次（按用户 ID 认，搭档带报名也认得出），显示活动名、轮次、日期、开打时间、场号、对手（双打加搭档），没定的写「待定」；只有活动开始时间时显示「活动 14:00 开始 · 本场时间待定」。昨天及更早的未录分场次不显示。点进活动详情的「场次」并定位到这场；返回首页、下拉刷新时重算。没有就显示「暂无下一场」。
- **分享**：活动详情右上角分享和「发给球友报名」按钮，封面现画（底图 `images/share-bg.jpg` 上写日期、时间、报名人数；底图加载不出来照旧画淡紫渐变），画不出来用固定封面 `images/share.jpg`（同一张底图 +「LULU网球」，邀请和准入页分享也用它）。
- **删除活动**：软删除，必须选原因，已录比分保留在战绩里。

### 战绩（tab 2，`pages/index` / `match` / `history` / `score` / `correct` / `add`）
- **只有一套正式战绩**（`utils/official.js`）。活动比赛只认云函数写入的记录；弃权、退赛、轮空用 `isNormal` 排除在统计之外。
- **录分即生效**：日常比赛和活动比赛都是一人录了就计入，不需要对方确认。
- **日常比赛**：正式成员都能新增（2026-11-23 起，原来只有管理员），只能录自己参加的比赛（按用户 ID）。没锁定的比分录入人和参赛者都能直接改（`editMatchScore`），立即生效。
- **已锁定的比分**（以前双方确认过的、管理员更正过的）：参赛者提交改分申请，对方同意后生效；活动比赛可以由发起人裁定。申请用 `claim()` 防重复、防并发，提交后比分又变了则申请失效。
- **影响后续场次**：活动比赛改分 / 撤销会推翻后续已录分的场次时，必须先确认影响清单，被推翻的记录作废并留档。
- **比赛详情**：「比分修改记录」（只显示操作人和比分，不显示原因）；比分修改、改分申请、管理员更正 / 撤销的入口。
- **亮点标签**：爆冷、逆转、终结 N 连胜、抢七、送蛋（`utils/highlight.js`，和徽章共用判断）。爆冷 = 赛前等级比对手低 0.3 以上还赢了，定级期（前 5 场）不算；终结连胜 = 对手赛前至少 3 连胜。
- **所有原因只能选**：改分、拒绝改分、裁定、退赛、弃权、拒绝退赛、撤销、影响后续场次的处理、删除活动、拒绝 / 移除成员，一律从 `E.REASONS` 选；旧的手写原因不再展示。

### 排行（tab 3，`pages/rank`）
- **水平分**：按得局率计算，含防炸鱼，起点是自评等级。内部按两位小数计算和排序，界面上按 0.5 一档显示（`R.fmt`），每场涨跌只显示 ↑ / ↓。
- 排序：按水平、按胜场，另有本月活跃、连胜、本月进步三个榜单。
- 可以按性别筛选，切换「生涯 / 某个赛季」（赛季 = 自然年；水平分不分赛季）。
- 只显示同意了公开展示的账号（没有账号的旧名字也不显示）；本人没开时，榜单上方有「开启」提示条。
- 名字太长换到第二行（最多两行），前三名领奖台同样。

### 球拍（tab 4，`pages/racket` / `racket-view` / `racket-edit` / `racket-log`，只有本人可见）
- 多支球拍，按添加顺序自动编号「N 号拍」；品牌、型号、状态、购入日期、备注都从固定选项里选。
- 每支拍记录穿线（竖 / 横线球线、混穿、磅数、费用、手感 1～5 分、备注标签）和维护（手胶、底胶、护线管、护框贴、避震器、配重调整、其他维护，带费用）。只有费用是数字输入。
- 按项目设置提醒间隔，从上次记录（没有就从购入日期）算下次日期；到期或 7 天内到期的数量显示在「球拍」tab 上，只在小程序内提醒。
- 按实际打球时长换线（2026-11-23）：详情页记每次打球的日期和分钟数，显示这次穿线以后已打小时数；可选「满 N 小时」提醒（默认关闭），和按天的穿线提醒合成一条，都到了只算一项。
- 统计：累计穿线 / 维护次数、上次穿线时间、费用合计、时间线。
- 球拍示意图按品牌 / 系列配色画（`<rk-art>`），不上传照片、不用品牌产品图。
- 页面顶部的统计卡片右边是一张固定配图（`images/racket-hero.png`，通用球拍、没有品牌，2026-11-22 加），只作装饰。
- 可以删除单条记录、删除球拍（连同记录）、清除全部球拍数据。页面不能分享。

### 我的（tab 5，`pages/me` / `profile` / `player` / `growth` / `members`）
- **个人资料**（`pages/profile`）：昵称（最多 10 个字，过内容检测、不能和别人重名）、性别（必填，男 / 女）、自评等级。
- **公开展示授权**：资料页勾选项「同意向其他成员公开展示我的昵称和照片」，不默认勾选、不强制，随时开关；老成员没选过的，启动后弹窗问一次。没同意的照片对任何人都不下发、不能上传照片、不进排行榜；报名名单、对阵表、比赛记录照常显示昵称。
- **球员照片**：只在资料页上传（相册 / 拍照 → 1:1 裁剪 → 1080×1080 JPG），经 `mediaCheckAsync` 异步检测，明确通过才给其他人看；本人上传后马上在所有页面看到。列表用 320×320 缩略图并存到手机（最多 200 张 / 20MB），点开大图用原图。本人可以删除，管理员可以移除。没有照片显示彩色首字圆。
- **球员主页**（「我的」和别人的主页共用 `components/player-home`，不能分享）：
  - 顶部是球员卡（2026-11-22；卡面不写「LULU 球员卡」标题，用户嫌 low 已去掉）：头像 / 首字圆、昵称、性别；比赛等级（大字）和自评等级分开标注，没有的写「待定级」，定级期显示「定级中 N/5」；卡片下方排名、场数、胜率（胜负写在卡下的说明里）。排名和排行榜默认榜（生涯 · 全部 · 按水平）一致，只在同意公开展示的账号里排；没同意的（含还没选的）显示「未公开」，本人卡下有提示。报名名单的「第 N 名」和战绩页「我的」卡片的「排名第 N 位」也是同一个名次（没开公开展示的，报名名单显示「未公开」、战绩页卡片显示「未开启公开展示，不在排行榜里」）。只在站内展示，不能分享或存图；
  - 近期比赛（别人的主页）和全部比赛入口；
  - 等级走势（最近 30 场）、双打搭档统计和最佳搭档、和 TA 的交手记录（别人的主页）；
  - 苦主 / 福星 / 最佳拍档：苦主、福星至少 2 场，最佳拍档要一起打满 3 场；
  - 生涯成就：冠军、最后一轮次数、参加活动数、最长 / 当前连胜、最高等级、单打 / 双打战绩、老对手、首场比赛；21 个徽章，没达成的显示进度。冠军按活动最后一轮的比赛记录认定（弃权胜也算），只有分组循环的活动不产生冠军。
- **成长档案**（`pages/growth` / `growth-edit`，只有本人可见）：私人比赛记录（日期、单打 / 双打、练习赛 / 正式比赛、盘分，胜负由比分算出，备注只能选固定标签）。统计场次、胜负、胜率、本月 / 上月对比、最近 6 个月走势、连胜，并显示一块只读的正式战绩摘要。和正式战绩分开统计、不相加，不进排行 / 等级分 / 球员主页。可以逐条删除或清除全部。
- **成员管理**（`pages/members`，仅管理员，在「我的」最下面）：审核申请、移除 / 恢复成员、生成邀请（可分享）、导入历史球友、给没填性别的老成员补选性别（留档）、复制用户 ID、数据核对（列出名字和账号对不上的旧报名记录，只检查不修改）。有待审核申请时「我的」tab 显示红点，入口显示待审核人数。

### 管理员额外权限（都会留档）
- 编辑任何活动的信息（名称、时间、场地编号、地图坐标），删除任何活动（必须选原因）。
- `adminFixScore` 直接更正任何一场的正常比分，不用填原因，更正后锁定。
- `revokeMatch` 撤销任何一场（日常、活动、已锁定的、弃权 / 退赛的），不用填原因。
- `adminClearPhoto` 移除球员照片；`setMemberGender` 补选性别。
- 活动比赛会推翻后续已录分场次时，更正 / 撤销都要先确认影响清单。
- 生成对阵、判弃权 / 退赛、裁定改分申请、处理退赛、单场安排仍然只有发起人能做。

### 性能与读取
- 读战绩和球员一次调用云函数 `dataset`，内容没变只回「没变」；超过大小限制或云函数是旧版时自动退回分页读取，两种方式结果一致。
- 活动详情页一次取齐（`drawDetail`），「我的活动」合成一次（`mySignups`）。
- 统计按用户 ID 累计，同名账号分开统计。
- 前端内存缓存 60 秒，写操作成功后自动作废；只读 tab 页数据没变时比较引用直接跳过重算；本机缓存异步写、内容变了才写。

## 二、数据库与存储权限（必须保持）

**所有集合都设为「仅管理端可读写」**（控制台里可能叫「所有用户不可读写」）。小程序端不直接访问数据库，一律经云函数 `tennis` 的数据网关（`data` 操作）。

| 集合 | 用途 |
|---|---|
| matches | 比赛记录 |
| players | 球员 / 个人资料 |
| draws | 活动 |
| signups | 报名 |
| verified | 正式战绩快照（含旧记录迁移标记） |
| confirms | 赛果确认 |
| requests | 改分 / 退赛申请及处理记录 |
| members | 成员资格 |
| invites | 邀请码 |
| avatar_checks | 球员照片检测记录（`_id` = trace_id，推送先到时暂存 `early-<trace_id>`） |
| rackets | 我的球拍：球拍档案（`owner`、自动编号 `no`；索引 `owner` + `no`） |
| racket_logs | 我的球拍：穿线 / 维护 / 使用（打球分钟数）记录（`owner`、`racketId`、`kind`：`string` / `maint` / `play`；索引 `owner` + `racketId` + `date`） |
| cup_stops | LULU 积分：管理员补录的每一站（`date`、`year`、`kind`、`format`、`places` 名次、`results` 结算、`status` 草稿 / 已发布、`fixes` 更正次数；`drawId` = 从积分活动结算的那一站（编号由活动 ID 固定算出，一个活动一站）；只经 `cupSave`（管理员）/ `cupFromDraw`（管理员，只读）/ `cupList` 读写，不在网关白名单里；索引 `date` + `kind` + `format`） |
| growth_matches | 成长档案的私人比赛记录（`owner` = 本人用户 ID，只由云函数写入；不在网关白名单里，只经 `growth*` 操作按本人读写；索引 `owner` + `date`） |

**数据网关的写权限**（`GW_OPS`）：
- 网关只允许两种写入：`matches` 新增日常比赛，`players` 新增「只有名字」的球员。其他写入都走专门的云函数操作。
- `players` 本人资料只能经 `saveProfile` 写入：服务端检查昵称不和别人重复（包括别人以前用过的昵称），照片只认本人 `avatars/<用户 ID>/` 目录。
- `draws` 只能经 `createDraw` / `generateDraw` / `updateDrawInfo` / `removeDraw` / `setFixtureSlot`（单场安排，只有发起人）写入，服务端逐个字段校验。`withdrawals` 只能由退赛流程写入。参赛名 → 用户 ID（`uidOf`）只接受报名记录或该账号当前资料能证明的对应。已经录分或登记过退赛的活动不能重新生成签表。删除活动是软删除：签表不再显示，联系人删除，活动相册的照片文件和记录删除，未处理的申请作废，已录比分保留。照片文件删除失败的，fileID 记在 `requests` 的删除记录里（`type: 'deleteDraw'`），需要在控制台手动清理。
- `signups` 只能经云函数 `signUp` / `cancelSignup` 写入。参赛名取本人资料里的昵称，搭档按用户 ID 校验，与其他球友重名时拒绝报名。签表生成后不能直接取消报名。
- `matches` 只允许新增日常比赛：正式成员都能录，但本人必须参赛（按用户 ID）。修改走 `editMatchScore` 或改分申请，删除走 `revokeMatch`。管理员可以在比赛详情里「更正比分」（`adminFixScore`，日常比赛和活动比赛都可以）：不用填原因，直接生效并留档（操作人、改前改后的比分），更正后比分锁定，待处理的改分申请随之失效；活动比赛会推翻后续已录分场次时，先列出影响，确认后才执行。
- `revokeMatch`：日常比赛的录入人和参加者（按用户 ID）都能撤销，已锁定的比分不能撤销。活动比赛中，参赛的录入人只能撤销「未确认、不影响后续场次」的正常比分；其他情况只有发起人能撤销，必须填原因，受影响的场次一并作废。管理员可以撤销任何一场（不用填原因，影响后续场次时先确认）。所有撤销都会写入 `requests` 留档（`type: 'revoke'`，管理员撤销带 `byAdmin`）。

**云存储安全规则**：
```json
{
  "read": "resource.openid == auth.openid && /^avatars\\//.test(resource.path)",
  "write": "resource.openid == auth.openid && /^avatars\\//.test(resource.path)"
}
```
存储目录：`avatars/<用户 ID>/`（客户端上传）、`player-photos/<用户 ID>/`（服务端快照，客户端不可读写）。以前的活动相册目录 `event-photos/` 已删除。

## 三、部署要求

1. 修改 `utils/rules.js`、`utils/draw.js`、`utils/event.js`、`utils/official.js`、`utils/growth.js`、`utils/racket.js` 之后，先运行 `scripts/sync-shared.sh`。
2. 部署云函数：在开发者工具里右键 `cloudfunctions/tennis` →「上传并部署：云端安装依赖」。
3. 云函数配置（云开发控制台 → 云函数 → tennis → 版本与配置）：
   - 超时时间：10 秒；
   - 环境变量 `ADMIN_OPENIDS`：管理员 openid，多个用英文逗号分隔；
   - `config.json` 已声明 openapi 权限：`security.msgSecCheck`、`security.mediaCheckAsync`。
4. 消息推送：云开发控制台 → 设置 → 全局设置 → 消息推送，添加 `event` / `wxa_media_check` → 云函数 `tennis`。
5. 数据库新建集合 `avatar_checks`（照片检测）、`growth_matches`（成长档案）、`rackets`、`racket_logs`（我的球拍），权限设为「仅管理端可读写」；索引：`growth_matches` 为 `owner` 升序 + `date` 降序，`rackets` 为 `owner` 升序 + `no` 升序，`racket_logs` 为 `owner` 升序 + `racketId` 升序 + `date` 降序。
6. 不需要配置订阅消息模板（已移除）。downloadFile 合法域名要有云存储域名 `https://<云存储桶名>.tcb.qcloud.la`（球员照片缩略图存到本机用，2026-11-20 已添加；换环境时要改）。
7. 用户隐私保护指引需要声明：昵称、头像（照片）（用途写经本人同意后向其他成员展示）、选中的照片或视频信息、摄像头（用途写「设置球员照片」）、位置信息（选择位置）。`app.json` 已声明 `chooseLocation`。
8. 首次升级到成员准入版本后：管理员打开「成员管理 → 历史球友」，逐个确认后导入。

## 五、已知问题与限制

- **已发出的照片收不回**：已下载的照片无法远程收回；已发出的临时链接在过期前（最长 30 分钟）仍可能打开。
- **非成员仍能上传文件**：云存储规则无法判断成员资格，未批准用户理论上能上传文件，但文件不会被登记、展示或被他人读取。
- **缓存短暂可见**：被移除的成员重新打开小程序时，在资格校验返回前（约数百毫秒）可能短暂看到 24 小时内的本机缓存。
- **云函数费用**：所有数据读取都经过云函数。已做的优化：分页改为每页 100 条；前端内存缓存 60 秒，并合并同时发起的相同请求（切换 tab 不再重复拉取）；我的活动等列表改为批量查询。缓存带来的代价是：别人新录的比分，最多要 60 秒或下拉刷新后才能看到。
- **签表名字是快照**：改名后，签表里仍显示生成签表时的参赛名；照片和关联按 ID 更新。
- **同名账号**：统计已按用户 ID 分开。旧记录（没有 ID）的名字如果同时被两个账号使用，这些旧记录单独统计，不算到任何一个账号上。
- **旧数据未绑定账号**：升级前的旧比赛没有用户 ID，只显示和统计，不能确认。
- **基础库版本要求**：`cropImage`、`compressImage` 的尺寸参数需要 2.26.0 及以上，`virtualHost` 需要 2.11.2。
- **旧报名记录未清洗**：本次修复前经网关写入的报名记录，名字是客户端填的。如果怀疑有冒名报名，需要人工核对 `signups` 里 `name` 和 `_openid` 是否对应。
